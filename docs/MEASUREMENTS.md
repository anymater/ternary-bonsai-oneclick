## 4. 下载速度（重要）

| 方式 | 速率 | 说明 |
|---|---|---|
| GitHub Release **单连接** | 约 **100–110 KB/s** | 6 GB 要十几个小时，不可用 |
| GitHub Release **16 并发静态等分** | 曾测到 **约 9 MB/s** | 同一个文件、同一网络 |
| GitHub Release **8 并发静态等分**（某次慢链路） | 1.47 MB/s | 372.9 MB 用了 254 秒 |
| ModelScope 直连 | 可达 1–1.5 MB/s | 国内源，模型默认首选 |
| **本项目的分块队列下载器**（8 工人 / 8 MB 块） | **4.4–4.5 MB/s** | 189.6 MB 用时 43 秒，SHA256 通过 |

**教训一：只测"源快不快"没有意义，必须用最终要用的下载方式实测聚合速率。** 同一源单连接和多连接能差 30 倍以上。

**教训二：静态等分不是多线程下载器。** 老实现把文件切成 N 段后一段一个 `curl`，谁先完成都不管——只要有一条连接慢或断掉，整体就卡在那一段上，其余连接早早空转。`tools\download.ps1` 改成了**分块队列 + 工作窃取**：

| 机制 | 做法 | 解决的问题 |
|---|---|---|
| 块粒度 | 切成 `工人数 × 8` 块（8 MB ~ 128 MB 自适应），远多于工人数 | 有空闲工人就还有活可领，不会出现"一个慢连接拖住全局" |
| 队列调度 | 工人干完一块立刻领下一块；失败块**重排到队尾**而不是原地重试 | 偶发失败不会反复撞同一段 |
| 块内续传 | 半截块保留，重下时把 `Range` 起点推进到已有字节数，新数据写 `.new` 再追加 | 断一次最多损失一块的传输，而不是整块 8 MB |
| 跨次续传 | 完成块与 `.plan`（URL+大小+块大小）留在磁盘，重跑只下缺的 | 关窗口/重启/断网后重跑能接着下 |
| 卡死检测 | 45 秒无增长就杀掉该块并重排 | `curl` 卡在死连接上不会永久挂着 |
| 防 Range 欺骗 | 逐块核对精确长度；某块实收等于整个文件大小即判定服务端无视 `Range` 并报错 | 静默拼出坏文件 |

**续传是实测过的，不是"代码里有"**：189.6 MB 下到 30.75 MB（8 块各 4,030,464 / 8,388,608 B）时强杀进程，重跑输出

```
  [计划] e.zip  共 189.6 MB   切成 24 块 x 8.0 MB   并发 8
  [续传] 已有 0 块完整（0 B），还需下 24 块，另有 8 块有半截、从断点接着下
  ...
  [通过] SHA256 一致
```

断点接错一个字节，SHA256 就过不了——所以"哈希一致"同时证明了合并顺序和断点偏移都对。

另一个坑：**有些反代会无视 `Range` 请求头**，对任意区间都返回完整文件（HTTP 200 而非 206）。这时各段长度全超标，拼出来是坏文件。所以 `tools\download.ps1` 会逐段核对精确长度，不符即清理重试，绝不放行。

## 5. 官方预编译包的两个真实障碍

这两个都是实跑踩出来的，直接影响"能不能直接用官方件"的决策：

### 5.1 CUDA 大版本写死在导入表里

`dumpbin /dependents` 结果：

| 构建 | 依赖 |
|---|---|
| 官方 `win-cuda-12.4-x64` 的 `ggml-cuda.dll` | `cudart64_12.dll`、`cublas64_12.dll` |
| 本机自编译版 | `cublas64_13.dll`（CUDA 运行时静态链接进去了） |

本机只装了 CUDA 13.3，所以官方 12.4 版直接报缺 DLL（表现为 `STATUS_DLL_NOT_FOUND`，退出码 `-1073741515`）。**换成官方 13.3 版立刻正常**。这也是 `detect.ps1` 要按驱动版本选资产的原因。

### 5.2 必须用 cudart 包做应用本地加载

官方 Release 的引擎 zip 里**不含** `cudart64_*` / `cublas64_*`，它们是单独的 `cudart-llama-bin-win-cuda-*.zip`（约 373 MB）。

验证方法：把 PATH 里的 CUDA 目录全部去掉后运行

```
PATH="C:\Windows\System32;C:\Windows" runtime\bin\llama-server.exe --version
```

输出正常：

```
version: 0.7.0-dev (build 12128, commit d7b289683)
built with MSVC 19.44.35229.0 for Windows AMD64
```

**说明用户机器不需要安装 CUDA Toolkit** —— 这正是本项目"零依赖"的前提。

- 分块队列下载器：189.6 MB 完整下载 + SHA256 通过（4.4 MB/s，24 块 / 8 工人）
- 断点续传：下载到 30.75 MB 时强杀，重跑从 8 个半截块继续，最终 SHA256 一致
- 净化 PATH（无 CUDA Toolkit）下引擎可运行
- `start.bat` 正确读取 `config\ctx.txt`：`n_ctx = 131072`
- 鉴权：`/health` `/` 免鉴权 200；`/props` `/v1/models` `/v1/chat/completions` 无密钥 401、有密钥 200、错密钥 401
